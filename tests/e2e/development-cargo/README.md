# Installed Cargo operation qualification

`qualification.json` records observed normal CLI executions against the
disposable target's exact pinned source generations. Thread/capsule identities
refer to that node's retained evidence; this file grants no execution, binding,
credential or publication authority.

`remote-environment-preparation.json` separately records the fresh local-remote
preparation/support producers, exact product composition and the failed utility
admission that exposed an origin-versus-placement check. The accompanying
source correction and focused tests are not installed utility-build or worker
edit/child/restart/candidate evidence. Historical Cargo qualification above is
unchanged.

The source-owned Tools are `.ai/tools/ryeos/development/cargo-{check,build,test}.yaml`.
They use captured files, isolated networking, exact platform/vendor manifests,
two Cargo jobs and a 300-second operation timeout. The root worker does not
receive those compiler trees. The separate signed environment requests the
finite operations through RyeOS's existing restricted workload client.

Qualification deliberately distinguishes:

- Successful operator-driven check/build and an exact test that really ran.
- A separate captured one-file error producing the expected failed test.
- The discovered nonshared glibc link omission and the corrected actual run.
- Exact completed success/failure results retained across a normal target
  restart, with source HEAD and the historical credential fence unchanged.
- Still-unqualified worker-driven, restart, candidate and remote behavior.

Source-level composition checks remain in
`../authoring-environment/test_development_contract.py`; they do not rerun
these installed operations or treat this evidence index as an admission grant.
